# ADR-007: LangGraph for Agent Orchestration

## Context
The platform features multiple AI agents (Code Evaluator, Interview Conductor, System Design Mentor, Knowledge Tracer, etc.) that need to collaborate, route tasks, use tools, and maintain conversational state. Managing these interactions with simple prompt chaining or standard LangChain is too rigid and complex for multi-agent workflows.

## Decision
We will use LangGraph for multi-agent orchestration and state management.

## Alternatives
- AutoGen: Good for multi-agent conversations, but LangGraph provides more explicit control over the state machine and flow graph, which is better for production predictability.
- Custom State Machine: Building a custom graph orchestrator is error-prone and reinvents the wheel.

## Advantages
- Explicit, graph-based control flow provides predictability and observability.
- Native support for cyclic graphs, crucial for agentic reflection and iterative tasks (e.g., code evaluation).
- Built-in persistent state management (checkpoints) via PostgreSQL (using PostgresSaver).

## Disadvantages
- Adds a learning curve for developers unfamiliar with graph-based orchestration.
- State schema must be carefully designed to avoid bloating the checkpoint database.

## Consequences
- Agent workflows will be modeled as nodes and edges.
- Agent state will be explicitly defined and isolated from the application's transactional database.
- Agents will interact with the system strictly through defined tools (APIs), not direct database connections.

## Status
Accepted
