# ADR-003: MongoDB Vector Search for RAG

## Context
The platform requires Retrieval-Augmented Generation (RAG) over company-specific preparation material, interview knowledge, and technical content. The system must store documents, chunks, metadata, and dense vector embeddings, while also supporting hybrid search (vector similarity + metadata filtering).

## Decision
We will use MongoDB (specifically MongoDB Atlas Vector Search) as the storage and retrieval engine for the RAG knowledge layer.

## Alternatives
- Pinecone / Milvus (Dedicated Vector DBs): Excellent vector search but require a separate database for storing document metadata, increasing infrastructure complexity.
- PostgreSQL + pgvector: Good for unified storage, but MongoDB offers a more flexible document model for varying web-scraped data structures and native vector search capabilities in Atlas.

## Advantages
- Unified storage for unstructured knowledge documents and their vector embeddings.
- Flexible schema accommodates diverse metadata from web ingestion.
- Built-in vector search capabilities combined with powerful metadata filtering.

## Disadvantages
- Managing MongoDB alongside PostgreSQL increases operational overhead.
- Requires careful index design for vector search performance.

## Consequences
- Documents and chunks will be stored as BSON documents with vector embeddings.
- Retrieval pipeline will leverage MongoDB's aggregation framework for hybrid search.

## Status
Accepted
