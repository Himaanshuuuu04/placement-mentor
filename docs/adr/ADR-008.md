# ADR-008: Judge0 + Firecracker for Code Execution

## Context
The system must compile and execute untrusted code submitted by students for coding assessments. Executing untrusted code poses severe security risks, including fork bombs, file system escapes, and network abuse.

## Decision
We will use Judge0 as the code execution API layer, backed by Firecracker microVMs for secure, hardware-level isolation.

## Alternatives
- Docker containers only: Containers share the host kernel. Container escapes (e.g., via kernel vulnerabilities) are a significant risk when running explicitly untrusted code.
- AWS Lambda: Good isolation, but execution environments are harder to customize per language, and latency/cost can be high for thousands of small, rapid executions.

## Advantages
- Firecracker provides strong security boundaries (hardware virtualization) with fast startup times suitable for serverless/transient workloads.
- Judge0 provides a ready-to-use API for compiling and running multiple programming languages, handling timeouts, and capturing stdout/stderr.

## Disadvantages
- Complex to set up and host locally (Firecracker requires KVM support).
- Managing microVM lifecycles and resource limits requires careful configuration.

## Consequences
- The Code Execution Service will act as a proxy/manager for Judge0.
- Strict limits (CPU, memory, time, network egress disabled) will be enforced on all executions.
- Local development may fallback to Docker-based Judge0, but production must use Firecracker.

## Status
Accepted
