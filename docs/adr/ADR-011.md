# ADR-011: Agent-to-Service Communication

## Context
AI agents (e.g., Code Evaluator, Interview Conductor) need to access platform data (student mastery, questions) and trigger platform actions. They operate non-deterministically and must not be allowed to bypass business logic or directly modify the system of record.

## Decision
Agents must interact with the platform exclusively through explicitly defined tools that wrap standard service APIs. Agents will never be granted direct database access.

## Alternatives
- Direct Database Access: Giving agents read/write SQL access is a massive security risk, bypasses application-level validation, and violates service boundaries.
- Monolithic Agent integration: Hardcoding the agent logic within the API service tightly couples non-deterministic AI flows with deterministic business logic.

## Advantages
- Security: Agents are constrained by the same authorization and validation rules as standard clients.
- Separation of Concerns: Deterministic business logic remains in the services, outside the LLM's prompt.
- Observability: All agent actions can be logged, rate-limited, and monitored at the API gateway.

## Disadvantages
- Requires writing wrapper tools/SDKs for the agents to interact with the internal APIs.
- Slight latency overhead due to network calls between the Agent Orchestrator and other internal services.

## Consequences
- LangGraph nodes will be equipped with specific tools (e.g., `update_mastery`, `fetch_question`).
- Internal APIs must be well-documented (OpenAPI) and robust against hallucinated or malformed inputs from agents.

Accepted
