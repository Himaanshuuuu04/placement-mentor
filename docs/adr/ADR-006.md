# ADR-006: Crawl4AI for Crawling

## Context
To build a comprehensive company-specific knowledge base, the system must ingest content from corporate websites, technical blogs, and documentation. This requires a tool capable of web crawling, JavaScript rendering, and extracting meaningful content from dynamic pages.

## Decision
We will use Crawl4AI as the core web crawler within the Knowledge Acquisition Platform.

## Alternatives
- Scrapy: Powerful and extensible, but requires significant setup for handling modern JS-heavy SPA websites (needs Playwright/Splash integration).
- Puppeteer/Playwright (raw): Requires building all crawling logic, queuing, and extraction logic from scratch.

## Advantages
- Designed specifically for AI/LLM data extraction.
- Handles JavaScript rendering and modern web architectures well.
- Simplifies the process of turning raw HTML into structured/Markdown formats suitable for RAG.

## Disadvantages
- May introduce a dependency on a specific ecosystem or library that might evolve rapidly.
- Resource-intensive (requires headless browsers), necessitating a dedicated, scalable Crawler Service.

## Consequences
- Crawl4AI will be deployed in isolated worker nodes that can scale independently based on the queue depth in Redis.
- Strict timeout, retry, and rate-limiting rules will be enforced to prevent infinite crawling and resource exhaustion.

## Status
Accepted
