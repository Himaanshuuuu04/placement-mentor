# ADR-012: Document Versioning and Provenance

## Context
The Knowledge Acquisition Platform scrapes web data to power RAG. Web content changes over time. When an AI agent provides an answer based on retrieved context, the system must be able to trace exactly which version of which document from which URL generated that context to ensure reproducibility and accountability.

## Decision
The system will implement strict versioning and provenance tracking for all ingested documents. Every chunk and embedding will be tied to a specific immutable `DocumentVersion`.

## Alternatives
- Overwrite existing documents: Saves storage but destroys the ability to debug past AI responses or reproduce past RAG context.
- No provenance tracking: Simplifies ingestion but makes the RAG system a "black box" where answers cannot be verified against their source.

## Advantages
- Reproducibility: Can recreate the exact context window an LLM used for a specific answer at a past date.
- Debuggability: Easy to identify and blacklist "poisoned" or low-quality source URLs.
- Audibility: Preserves the chain of custody from `Source URL → Document → Version → Chunk → Embedding → Retrieval Result → Generated Answer`.

## Disadvantages
- Increased storage costs for raw documents and embeddings.
- More complex deduplication and update logic during recrawling.

## Consequences
- Storage in S3 and MongoDB will include version tags (e.g., `v1`, `v2`).
- Recrawling a URL will create a new `DocumentVersion` if the content hash has changed, rather than mutating the existing record.
- The retrieval API will return citation metadata (URL, version, chunk ID) alongside the context text.

## Status
Accepted
